# 真实照片首轮验证（2026-09-30）

## 结论与适用范围

完成普通数字标志的候选定位，以及不预先知道标志相对位置的平面尺寸反算。6 张开发照片的长宽误差均在 ±50 mm 内，最大绝对误差 33.1 mm；但 **6 张质量状态全部为 REVIEW（待复核）**。标志几何一致性尚不足，构件边界由助手目视选取，不能将这轮结果表述为“AI 自动测量准确率 100%”或现场验收通过。

这是独立试验，尚未接入网站，也未训练构件分割模型。现有网站仍使用原有 ArUco 流程。

## 数据及测量口径

- 压缩包有 39 张原图和 39 张对应水印图。本次只使用原图，水印副本不作为额外训练样本。
- 用户已确认：文件名中的两组尺寸是卷尺实测长宽，单位 mm；本次标志最外黑框边长按已确认的 150 mm 使用。
- 为避免拍摄方向影响，将两组卷尺数值的较大者记为长、较小者记为宽。数字仅在计算完成后的评估阶段读取，不作为标定或尺寸推算输入。
- 标志是普通数字方形图案，不是 ArUco。本次识别图案位置，不解码数字；结果中的候选序号不代表纸上的编号。
- 39 张照片按文件尺寸有 24 种长宽组合，但不能据此认定有 24 个不同构件。同一构件的不同视角必须分到同一数据分组，不能跨训练集和测试集。
- 原图、哈希、尺寸与来源记录在 `samples/real/20260930/reference_measurements.json`。

选择原则：上表面较完整、平整且有 4 个标志候选。不是随机抽取，也不是独立测试集。6 张中可能有同一构件的不同视角，不计作 6 个独立构件。

## 为何仍然待复核

标定由多个同平面方形标志的四边及对角线约束求解，不需要先输入构件长宽，也不要求已知标志之间的距离。方法采用平面投影与非线性拟合，基础分别参考 [OpenCV 单应性说明](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html) 和 [SciPy least_squares 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)。本项目的自定义组合算法及阈值仍需实测验证。

目前全部 6 张至少有一个标志的边长/对角线拟合误差超过试验阈值 7.5 mm。其中 0930152743、0930153657 的构件对边差还超过 50 mm。即使对边平均得到的尺寸接近卷尺值，局部几何不一致仍应保留复核提示。

部分标志从白色内框扩张得到外框搜索初值，再细化角点；扩张比例参考所给图案。角点细化不保证始终落在真实最外黑框，标志边缘需要进一步人工核对。尚未单独消除镜头畸变、纸张翘曲及不共面影响。

程序同时计算逐个去掉一个标志后的尺寸变化，检查标定敏感性；这只是内部一致性检查，不是独立精度证明。阈值没有根据本次卷尺误差放宽。

## 复现

在项目根目录运行，原图与标注须位于以上目录。真实数据和输出未纳入 Git；复制源码到其他电脑不会自动带上它们。绘图脚本当前使用 Windows 微软雅黑字体。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-pilot.txt
.\.venv\Scripts\python.exe scripts/audit_custom_markers.py
.\.venv\Scripts\python.exe scripts/run_real_pilot.py
.\.venv\Scripts\python.exe -m pytest -q
```

输出包括全量 `detections.json`、6 张的 `pilot_results.json`、标志图及 `*-measurement.jpg` 结果图。实测参考只参与评估，核心推算函数不接收卷尺值。

测试结果：47 项通过，含未知标志位置/旋转的合成场景、尺度变化、不足标志、错误边界、错误角点复核和图案干扰测试；2 条现有依赖弃用警告。测试通过只证明这些软件检查通过，不证明现场精度。
