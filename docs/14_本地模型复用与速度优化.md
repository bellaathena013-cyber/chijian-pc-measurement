# 本地模型复用与速度优化（2026-10-02）

本轮只优化模型进程启动和加载方式，不调整模型权重、识别阈值、角点算法或尺寸质量检查。

## 已实现

- 网站首次测量时启动本地模型工作进程，随后在同一进程内复用模型，避免每张照片重复导入 PyTorch 和读取权重。
- 原始单图命令仍可独立运行，网页与命令使用同一段预测代码。
- 请求串行处理，用独立请求编号匹配响应；每张照片仍有独立目录和日志。
- 每次请求检查权重内容摘要，权重变化后重新加载模型。
- 超时上限仍为 180 秒；超时、异常退出或响应不匹配时终止进程，下次请求重新启动，避免把上一次响应误当本次结果。
- 网站正常关闭时清理模型进程，工作进程在输入管道关闭后退出。模型驻留会占用内存，换取后续请求减少加载开销。
- 全部在本机完成，不新增外部服务、模型下载或照片上传。

## 验证

完整测试 84 项通过，2 项原有依赖弃用警告。新增进程测试覆盖复用、关闭、超时终止、异常退出、错误响应编号和下一请求恢复。

性能测试使用两张既有照片：一张能计算但需要复核，一张标志不足。先分别用独立命令运行，再通过同一个模型进程按“照片 A、照片 B、照片 A”运行，逐项比较完整 prediction.json，验证切换照片后没有残留上次预测。

初轮与测试并行的计时仅留作开发记录，不用作正式提速对比。最终计时在测试结束后执行，记录于 outputs/runtime-optimization-20261002/isolated/benchmark.json。该计时仅覆盖模型命令调用，网页还包括上传、图片归一化和诊断图生成，不能把命令耗时直接等同网页响应时间。

## 使用

最终模型调用实测：照片 A 独立命令 19.07 秒、照片 B 19.50 秒；工作进程首次请求 19.32 秒，随后 B 为 2.19 秒、再切回 A 为 1.68 秒。两张照片所有字段与独立命令一致。这是本机两张历史照片的少量计时，不是所有设备或照片的速度保证，也不是精度提升。

实际 HTTP 上传验证（同一原始照片连续两次，包含服务端图片处理）：首次 19.44 秒、第二次 2.74 秒。两次均为 2792.8 × 1412.6 mm、REVIEW；结果下载和全部图片地址均正常。记录见 `outputs/runtime-optimization-20261002/web-benchmark.json`，运行编号分别为 `0767cca23a8b46348895e22307ee3300` 和 `cc77c38dd44443b6b798ce2837db692b`。这里只计请求到返回结果，浏览器后续绘图耗时未计入。

继续运行 start-workbench.ps1 并打开 http://127.0.0.1:8765/ 。无需更改上传操作；首次请求仍需加载模型，连续测量才享受复用。原有历史结果不重写。
